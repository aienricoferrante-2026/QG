2 Come scorrono i dati

Una regola sopra tutte: Hub è l'unico punto in cui si configurano le integrazioni esterne. Tutte le webapp leggono env vars propagate via Vercel API. Le anagrafiche centrali (clienti, contatti, BU/BS, sedi, società) vivono in Hub e le altre app referenziano via FK.

⛔ Esclusione esplicita: le caselle PEC restano fuori dall'ecosistema webapp (regola ferma 2026-05-24). Gestione manuale sui client PEC nativi per valore legale.

! Le 6 regole ferme dell'ecosistema

1 · Integrazioni esterne SOLO in Hub

Microsoft 365, SharePoint, Anthropic, future API: un solo punto di configurazione. Le altre webapp leggono env vars propagate via Vercel API. Niente briefing separati a Lillo/IT.

2 · PEC fuori scope per sempre

Decisione 2026-05-24: valore legale troppo alto. Niente IMAP, niente sync, niente AI su PEC. Solo gestione manuale sui client PEC nativi.

3 · Supabase-first, QNet in dismissione

Webapp + Supabase è il target, non un workaround. QNet svuotato dominio per dominio. Niente nuove funzionalità ERP-first su QNet.

4 · Field-level System of Record

Per ogni singolo CAMPO si decide chi è padrone (Supabase o QNet), non per tabella. Registro in field_ownership Hub. Audit di sync obbligatorio.

5 · Polish = Definition of Done

Pagine home / manuale / wiki / sezioni hero seguono lo standard delle infografiche HTML: palette aziendale, KPI numeroni, pill colorate, diagrammi SVG inline. NO default shadcn passivi.

6 · Deploy = sempre via GitHub

Push branch → PR → merge via gh pr merge --squash --delete-branch --admin. Niente "preview localhost" come consegna. Vercel constraint: 100 deploy/giorno su free.
